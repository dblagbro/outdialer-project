# Python API/worker security runtime

This candidate keeps application, database schema and Asterisk source unchanged. It pins the Python 3.12 Debian Trixie base by digest, installs current distribution security updates, upgrades FastAPI/Starlette/AnyIO/multipart to compatible fixed releases, and installs a complete hashed Python wheel lock. Remaining pinned application dependencies are retained to limit unrelated behavior changes. The lock is for Linux amd64 / CPython 3.12; regenerate and validate a separate lock before building another platform.

Build and test from the repository root:

```sh
docker build -t outdialer-runtime:test services/outdialer
python3 scripts/test_api_runtime.py --image outdialer-runtime:test
```

The test runner creates an internal Docker network and memory-only synthetic PostgreSQL database, publishes no host ports, uses no production credentials or data, and removes only the containers/network that it created. Seventeen checks cover HTML/health, disabled campaigns, URL-encoded and multipart forms, database/AGI result persistence, error handling, CSV exports, recording byte ranges and worker imports. A repeated schema initialization preserves synthetic state. It never runs the campaign worker, SIP calls or external AI services. The initial delete fixture lacked the browser Referer; the corrected test passed on the same unchanged candidate image.

Fresh candidate scan: **0 Critical / 47 High**, compared with the retained original-image scan **4 Critical / 111 High**. The remaining High matches have no fixed version listed in that scan and remain subject to vendor/applicability review. Counts are package matches, not proven exploit paths. Exact image, lock, scan timestamp and finding IDs are recorded in the adjacent JSON.

**Not yet deployed.** Production API/worker replacement requires a consistent private database backup, isolated restoration and original-image rollback validation, scoped Compose checks, sequential rollout and live health/authentication checks. Preserve caller settings, spool/log/recording volumes and existing Asterisk state. Full SIP/provider acceptance remains untested; a dependency-only API/worker rollout does not authorize a call or restart a stopped telephony service. The general release checklist still applies to a complete telephony/product release.

To refresh the lock, resolve requirements.txt with pip --dry-run --ignore-installed --only-binary=:all: --report in the pinned base. Record each resolved name/version and PyPI wheel SHA-256 as requirements.lock. Build with --require-hashes, run pip check and isolated tests, and scan the exact candidate image before rollout. Debian repository updates mean rebuilding can produce a newer OS layer; retain and deploy the exact tested image/digest.
